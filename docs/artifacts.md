# Artifact Viewer — depth

The artifact system tracks every file Claude Write/Edit/Deletes into per-project sidecars + a central index, and renders them in the chat Session Drawer and the Project View hub. `ArtifactStore` state lives in the renderer (`state/ArtifactContext.tsx`, `state/artifact-tracker.ts` subscribes to TranscriptWatcher events alongside the chat reducer); all file I/O is main-process behind `window.claude.artifacts.*` IPC — the same pattern as the chat reducer, which is what lets the shared React UI render identically on desktop + Android.

## Tracking pipeline

- **`artifacts:append-version` is the IPC that populates the sidecar.** `listSession` is read-only (filters the sidecar by sessionId). Without the renderer Tracker calling `appendVersion` on every Write/Edit/MultiEdit tool-use event, the sidecar stays empty. Chain: Tracker → `appendVersion` → `ensureProject` → `applyGitTreatment` → broadcast `changed`. First thing to check when artifacts don't materialize. The Tracker itself is `renderer/state/artifact-tool-use-tracker.ts` (`createArtifactToolUseTracker`, built once in App.tsx); it is pure, and `tests/artifacts/artifact-tool-use-tracker.test.ts` pins what it tracks and how it refreshes.
- **The Tracker cannot tell replayed history from live events, so the whole path must be burst-safe.** Opening a conversation delivers EVERY tool call it ever made through the same handler, twice over: `TRANSCRIPT_REPLAY` streams `getHistory()` on the live channel, and `TranscriptWatcher.startWatching` reads the JSONL from `offset: 0` and emits it as live. A long session is ~1,000 Write/Edit/Read events at once. On 2026-08-15 that killed the app 16–21 s after opening one session — every `appendVersion` parsed and rewrote a 4.4 MB sidecar concurrently, each holding its own copy while it waited on the mkdir lock, until the main process hit "JavaScript heap out of memory". Three guards now hold: (1) `appendVersion` is a per-project **queue** — concurrent callers are applied in one read/apply-all/write cycle (`appendVersionsDirect` is the unqueued primitive; memory is one parsed sidecar per project no matter the burst); (2) `ensureProjectCoalesced` / `applyGitTreatmentCoalesced` answer a burst with one index write and one `.gitignore` read (30 s / 60 s TTL, in-flight sharing); (3) the Tracker refreshes the drawer via `listSession` ONCE per session after a 250 ms quiet period, not once per event. Guards: `artifact-store.test.ts` → "burst coalescing", `project-manager.test.ts` → "…Coalesced", `artifact-tool-use-tracker.test.ts`.
- **Replays are idempotent by `toolUseId`.** Every version the Tracker appends carries the transcript `tool_use` id (`VersionEvent.toolUseId`, optional and additive; mirrored in `SidecarSchema.kt`), and `appendVersion` skips a version whose `(sessionId, toolUseId)` already exists on the record — no write, no `updatedAt` bump, no `changed` broadcast. Before this, every re-open of a conversation appended its edits AGAIN, which is the mechanism behind the sidecar's unbounded growth (14,385 versions / 2,996 files / 4.4 MB in youcoded-dev by 2026-08-15) — closed for native sessions and same-session duplicates; see the scope note below for CC resumes. **Scope, corrected in review (2026-08-15): idempotent per DESKTOP session id.** Native sessions keep their id across resumes, so re-opening one is a true no-op; a Claude Code `--resume` mints a fresh desktop id (`session-manager.ts` `randomUUID()`), so a resumed CC conversation is re-recorded once per resume under the new id — bounded and crash-free thanks to the queue, but still growth. That re-recording is also, today, what populates the resumed session's drawer (`LIST_SESSION` and `SessionDrawer.tsx` `versionsInSession` both filter by desktop id), so making it idempotent means threading a conversation-stable id (the CC session id from `sessionIdMap`) through the record, the list filter, and the drawer helpers — a roadmap item (workspace `docs/roadmap/files.md`, the resumed-Claude-Code-conversation entry), not a one-liner. Records written before the field existed are re-recorded once (with the id) on their next replay. Callers without a tool call (manual include, viewer Save) leave it unset and keep always-append. Guard: `artifact-store.test.ts` → "replay dedupe by (sessionId, toolUseId)"; Kotlin `ArtifactStoreTest.appendVersionDedupesTheSameToolCallAndKeepsToolUseIdOnDisk`.
- **Version history is pruned on write: 30 days, floor of 10 per file.** `versions[]` used to grow forever (6.4 MB / 21,311 versions in youcoded-dev by 2026-08-27), and every save and listing parses the whole file. `pruneSidecarVersions` now runs inside `appendVersionsDirect` — and inside Kotlin `appendVersion` — so the sidecar is bounded BY CONSTRUCTION: **there is no migration and no startup scan**, an oversized file heals on its next write, and a file never written again was never growing. The policy lives in exactly two constants, `VERSION_RETENTION_DAYS`/`VERSION_RETENTION_FLOOR` (`shared/artifacts/version-retention.ts`, mirrored in `VersionRetention.kt`). Four things are never dropped, whatever their age: the floor, the newest entry (`status` derives from it — `migrate-relative-externals.statusFrom`), the newest **non-`read`** entry (`trackedArtifacts` rule 3 hides a record with no non-read version, so losing the lone `create` on a long-untouched-but-often-viewed file would make it vanish from Project View), and anything whose `ts` won't parse. Pruning runs BELOW the dedupe early-return, so "a re-opened conversation writes nothing" still holds. **Known consequence:** pruning an old `(sessionId, toolUseId)` pair also drops its replay-dedupe key, so re-opening a conversation older than the window re-records its edits under fresh timestamps (bounded — they are recent afterwards — and already the behaviour for CC resumes, which mint a new desktop id). Guards: `desktop/tests/artifacts/version-retention.test.ts`, `app/src/test/.../VersionRetentionTest.kt`.

- **Transcript events don't carry `cwd`.** The watcher emits `{ type, sessionId, uuid, timestamp, data }`; the Tracker resolves cwd via a `sessionsRef` lookup into `sessions` state. Reading `event.cwd` always bails silently.
- **`bash mv`/`bash rm` produce ZERO artifact events** — the Tracker only sees Write/Edit/Delete tool calls. Bash filesystem side-effects are opaque in v1. Because CC has no Delete tool, files are usually removed via `bash rm` → the record stays `status:'active'` with the file gone ("orphan"). Badges/counts subtract orphans via `checkExistence`. **One shared, cwd-keyed cache answers "which files are gone" for the whole renderer** (`renderer/hooks/useMissingArtifacts.ts`); the drawer list and the header badge both read it.
- **`sessionArtifacts` is backfilled from the sidecar when a session is active** (`ChatView` calls `listSession(sessionId, cwd)` ungated by drawer-open) — the live tracker only APPENDS, so after a reload the drawer showed "0 artifacts" until the next write. Don't remove.
- **`.youcoded/` is auto-gitignored** by `ProjectManager.applyGitTreatment()` (TS + Kotlin) on first sidecar materialization in a git repo — agent file-touch history doesn't leak into commits. Unconditional whenever `.git` exists (`project-manager.ts` `applyGitTreatment`) — there is no Settings toggle for it.
- **`transcriptRef` is NOT in v1** — dropped because CC's transcript format is version-coupled and CC compacts/rotates. v1 reads current content from disk; v2's version history will snapshot into `<project>/.youcoded/content/<versionId>` at write time. Don't reintroduce.

## Concurrency (`cas-write.ts`)

- **`casWrite` uses a mkdir-based lock, not just compare-and-set.** The initial CAS-then-rename had a TOCTOU race (two writers both pass CAS, both rename — one overwrites; commit `2d44fc3d`→`a75492ea`). Both TS + Kotlin (`CasWrite.kt`) use a `<target>.lock` dir + 30s stale-lock breaking. Don't simplify the lock away — the bug WILL recur.
- **Central-index writers use `mutateFileUnderLock` (read-modify-write INSIDE the lock)** — the index has no CAS version field, and the dev instance + built app share `~/.claude` (cross-process interleaving is normal). `casWrite` + `mutateFileUnderLock` share `acquireLock`/`atomicWrite`.
- **Every READ goes through `readSidecarShared` unless it mutates and writes back (2026-08-27 OOM, youcoded PR #335).** PR #318 queued the writer and left all 20 read sites unguarded; one Edit costs ~11 full parses (`LIST_SESSION`, `artifacts:get` per visible tool card, check-existence, the watcher's id map, every open tab at startup) and under a burst those pile up — the 2026-08-27 core dump held 477 parsed copies of a 6.4 MB sidecar ≈ 3.0 GB, two last-resort Mark-Compacts freeing 0 bytes. `readSidecarShared` keeps ONE parsed copy per project: validated by size + mtime (a stat, not a read, so another process's write is always seen), concurrent callers share the in-flight parse, a committed `writeSidecar` seeds it with the object it just wrote (the reads after every edit cost nothing), idle copies drop after 60 s. The shared object is read-only by contract — `appendVersionsDirect`, `removeArtifactRecord`, `renameArtifact`, `runSidecarMigration`, the manual include/exclude handlers and `import-project` keep the private `readSidecar`, because a writer mutating the shared copy would leak a never-committed state into every reader. `casWrite` reads its comparand from a 4 KB head probe (regex) with a whole-file fallback — the old extractor `JSON.parse`d the whole file for one timestamp on every write. Reproduced before/after against Destin's real file (`old N=477` → the journal's exact OOM; `new N=477` → 1 parse, 25 MB). Guards: `sidecar-cache.test.ts`, `cas-write.test.ts` → "head probe", `artifact-store.test.ts` → "zero JSON.parse on the CAS path". Full evidence: workspace `docs/archive/investigations/2026-08-27-artifacts-sidecar-oom-crash.md`. Android has neither this nor #318's queue — workspace `docs/roadmap/android-only.md` ("the phone's file-record store has neither the write queue nor the read guard").
- **`appendVersion` retries CAS `MAX_RETRIES=5`** — intentional; increasing it doesn't help under sustained contention (surfacing a warning is the escape valve). Same on Kotlin. Since 2026-08-15 the retry wraps a whole queued BATCH (see Tracking pipeline); same-process callers no longer contend with each other at all, only with a second process.

## Project Files (Artifacts/All-files split 2026-06-15, MERGED to one section 2026-07-23)

- **ONE `Files` tab, ONE section** (the `Artifacts` tab was merged away 2026-07-23). `Project Files` = the folder on disk (`LIST_ALL_FILES`/`countAllFiles` → `projectAllFiles(root)` = discovery UNIONed with tracked-on-disk **internal** artifacts, deduped by `canonicalize()`, so it can never report fewer files than there are tracked in-folder files — a real bug once: a code-heavy/nested-repo project had more artifacts than "all files". The union restores artifacts inside a skipped nested sub-repo). **In-folder artifacts are deliberately UNDIFFERENTIATED**: inside the project folder the disk is the truth, so do not badge, group, or re-split them. NOTE `ipc-handlers.ts` called `LIST_ALL_FILES` "pure discovery, independent of the sidecar" until 2026-07-23; that was wrong — read `projectAllFiles`, not the handler comment. An `External Artifacts` section (sidecar records outside the folder) shipped briefly the same day and was REMOVED: against real sidecars it was ~95% incidental noise (scratchpad temps, other-device Windows paths, `.claude/` internals), because "Claude edited a file outside the project" happens constantly and incidentally. Externals live in the **Session Drawer** per session (via `LIST_SESSION`), never Project View. Do not re-add the section.
- **Renderer segments are `Files | Conversations | Context`** (three, since the merge). `FilesTab` has no `mode` prop any more — it always renders the on-disk walk (the externals section and the Exclude button were removed from `FilesTab`; `artifacts:exclude` survives only as a transport channel). It is a navigable folder TREE (`listDir(files, currentDir)`): single files sort before folders; breadcrumb navigates up; search FLATTENS. The shared `SearchFilterPill` + multi-select type filter (`fileTypeGroup`; EMPTY set = all types) + sort live in `FileFilterPopover`, which is now shared with the **SessionDrawer**; search matches FILE NAMES only. Badge counts stay folder TOTALS, not filtered counts. "Hide code & configs" and sort-by-type were both retired 2026-07-23 (code is just one of the types). **"Show deleted" is SESSION-DRAWER-ONLY** — Project View dropped it because `VersionEvent` carries no content, so a deleted record is a tombstone, not a recovery path; the flag is a cross-device-SYNCED preference, so do not delete it as "unused" (guard: `session-drawer-deleted-toggle.test.tsx`). `+ Add file` now IMPORTS (Move/Copy into the browsed folder) rather than pinning; `Exclude` is external-rows only and has NO in-app undo.
- **Discovery (`project-file-discovery.ts#discoverProjectFiles`) scans every file type** (only `isNoiseFile` byproducts skipped — lockfiles, `.map`, `.min.js/.css`; NO extension allowlist), excludes `node_modules`/dot-dirs/`SKIP_DIRS`, never follows symlinks, **STOPS at nested git repos** (`.git` dir OR file — so youcoded-dev lists its own tree, not a crawl through cloned sub-repos), hard-bounded (file/dir/depth caps + 1.5s budget), cached 10s. The nested-repo stop makes the count DETERMINISTIC (before it: hero said 282, switcher said 1209). Discovered records carry `discovered: true` (NEVER persisted) — consumers skip them in `checkExistence` (ids are relative paths, not sidecar ids → wrongly flagged missing) and count them as always-present. "Exclude" is hidden for discovered files.

## Project list & counts

- **Project list = SAVED FOLDERS (`~/.claude/youcoded-folders.json`), NOT the central index.** `LIST_PROJECTS_INDEX` builds via `buildSavedFolderProjects(savedFolders, indexProjects)` (pure): each saved folder is a project; a central-index match by canonical path is reused (real ULID + stats), else a SYNTH entry whose `id` IS the canonical path. The index only gains an entry once Claude writes a tracked artifact, so folders with only conversations were invisible. Index-only projects that aren't saved folders are DROPPED.
- **`LIST_PROJECT`/`GET`/`SAVE` fall back to id-as-PATH (traversal-guarded)** — synth projects have no index entry; `path.resolve(projectRoot, artifactId)` REFUSES anything escaping the root. This is also how discovered files load/edit by path.
- **Two single-source count helpers in `artifacts/projects-index.ts` (imported by `ipc-handlers.ts`):** `countArtifacts(root)` (non-deleted tracked files still on disk — orphans excluded) = the ARTIFACTS number; `countAllFiles(root)` (discovery length) = the ALL FILES number. Hero segment badges/stat line + switcher row each read the right one. Don't recompute inline (the 282-vs-1209 drift). The hero count is LIVE; the switcher row falls back to the seeded `stats.artifactCount` until `withCounts` resolves, and permanently for gated roots (`ProjectSwitcher.tsx`).
- **Project switcher rows show "N files · M chats" where files = `fileCount` (ALL FILES)**, via `listProjectsIndex({ withCounts: true })` — a heavy global `listPastSessions` + per-project counts, too heavy for ChatView's frequent cwd-resolution (uses the fast no-arg form). `fileCount`/`conversationCount` on `CentralIndexProject` are read-time only, never persisted.
- **Conversations/Context tabs are CONTROLLED** (data lifted to `ProjectView`, per-project cached). `listProjectConversations` uses a bounded 64KB head-read per session (NOT `loadHistory(all)` — the dominant stall). Hero runs four IPCs in `Promise.all` (`ProjectView.tsx`).

## Visibility (`visible-artifacts.ts`, 2026-07-08)

- **`trackedArtifacts()` is the ONLY place tracked visibility is decided.** Order: manually INCLUDED (any kind — includes WIN over excludes) → manually EXCLUDED hidden (sticky across Claude re-edits) → **internal with ≥1 NON-READ version; externals hidden unless pinned**. (Rule 4 was briefly flipped 2026-07-23 to show unpinned externals in a Project View section, then reverted with the section — an ungated external set is ~95% incidental noise.) Rule 1 keeps LEGACY pins visible on upgrade; rule 2 is what `Exclude` writes. Pill-click `read`-only views deliberately don't appear (they live in Project Files + the drawer). Include/exclude entries are canonical ABSOLUTE paths — canonicalize BOTH sides (Windows drive-case made "Add file"-ed externals vanish).
- **The SessionDrawer is a session ACTIVITY LOG — it auto-tracks EVERY file Claude touches, external ones included** (`kind:'external'` + `absolutePath` in the sidecar). Do NOT restore the original spec's "externals never tracked" rule: the drawer becomes wildly confusing if Claude edits a file in the session and it doesn't show up. Externals live in the drawer and ONLY the drawer — Project View has never kept them (the 2026-07-23 External Artifacts section was reverted the same day).
- **`manualExcludes` MUST stay wired into `trackedArtifacts`** — it shipped write-only once (Exclude button inert). `EXCLUDE` un-pins + adds the exclude; `INCLUDE_EXTERNAL` also ENSURES a record exists (`appendVersion` `read`/`user`).
### Orphan detection (why it is a shared cache, not component state)

The check is ASYNC, so whoever holds the answer decides whether the list is
right on its first painted frame. Four things are load-bearing:

- **Never cleared before its replacement lands.** The drawer used to keep its own
  copy and reset it to empty on close, so every open painted deleted rows and
  removed them one round trip later (the 2026-08-30 "deleted files flash").
- **Keyed on the session CWD, not `projectRoot`.** `projectRoot` resolves through
  an async projects-index lookup and is `''` for the first frames of every open —
  exactly the window the check has to beat. The cwd is known immediately and is
  what the header badge already used, so the two share one warm answer. The key is
  canonicalized (`shared/artifacts/canonicalize.ts`): two spellings of one folder
  must not start cold.
- **The drawer refreshes on the whole artifact ARRAY, not the id set.** A rename, a
  status flip, or Claude re-creating a file it had deleted all change disk truth
  without changing ids; watching only ids left a stale "deleted" until close/reopen.
  Identical back-to-back requests coalesce, so this costs one round trip.
- **The settle-hold needs a floor AND a ceiling.** The list holds one frame rather
  than paint rows it is about to remove — but `cwd` is optional at both call sites
  (no folder → never hold) and a check can hang (500 ms → paint anyway). A blank
  file pane is a broken feature; the flash was only a cosmetic one.

Guards: `tests/missing-artifacts-cache.test.tsx`, `tests/session-drawer-settle-hold.test.tsx`.

- **`SessionDrawer` excludes `discovered` records from `checkExistence`** (`filter(a => !a.discovered)`) — relative ids hit the "unknown id → missing" branch and wrongly flagged on-disk files as deleted. SessionDrawer resolves the OPEN document against the UNFILTERED list (toggling a filter must not blank the content pane).
- **`artifacts:changed` broadcasts carry the REAL artifact id** (`appendVersion` returns it) — it was `null`, so the "Claude also edited this file" conflict banner could never fire. A `read` version records the view but does NOT bump `lastModified` (bumping reordered "recently modified" on every pill click). `artifacts:remove-record` deletes the RECORD only, never the file.

## Binary viewers & security (2026-06-17 / 2026-07-08)

- **`artifacts:read-binary` is GUARDED on desktop** (`read-binary-access.ts`, pure + tested): reachable over the remote WS, so reads are restricted to (a) saved-folder + central-index roots, (b) tracked external paths/manual includes, with well-known secret locations (`.ssh`, `.gnupg`, `.aws`, `.netrc`, `.credentials.json`, `.config/gh`, …) refused even inside allowed roots (the seeded "Home" saved folder makes most of home a root — the sensitive check carries the weight). 50MB gate (`too-large`) since base64 inflates 33% over IPC/WS. The Kotlin handler is guarded too as of 2026-07-22: `EditablePathPolicy.kt` ports the sensitive-path deny + 50MB gate (shared fixture `shared-fixtures/artifacts/editable-path-policy-cases.json`).
- **Binary viewers load bytes via `artifacts:read-binary` (base64), NEVER `fetch('file://…')`** — the renderer origin can't fetch `file://` (fails silently). `useArtifactBytes(absolutePath)` → `atob` → `Uint8Array`. `ImageView` builds a `blob:` URL. Full 4-surface parity pinned by `ipc-channels.test.ts`.
- **All binary viewers go through the `BinaryContent` shell** (`artifact-views/BinaryContent.tsx`) — owns loading/error (maps `orphan`/`too-large`/`not-allowed`/`unavailable`), keys the inner viewer by `absolutePath`. PdfView once ignored loading/error → blank pane on a corrupt PDF; it must `loadingTask.destroy()` in cleanup. **`ViewerErrorBoundary` wraps the lazy render in `ActiveArtifactView`** — `React.lazy` THROWS chunk-load failures that `<Suspense>` can't catch.
- **xlsx viewer is ExcelJS, not SheetJS (removed).** SheetJS free can't read cell styles; ExcelJS reads them free. `exceljs-cell.ts` (pure) maps cell → text + CSS; `XlsxView` renders a DOM grid padded to ≥50×26. **Formula cells must be evaluated** — openpyxl/pandas write formulas without cached results (`{formula}` → `[object Object]`). `xlsx-formula.ts` evaluates (memoized, cycle-guarded; IF short-circuits; /0 + non-finite THROW → blank, never `Infinity`; unsupported fns → blank). In-app xlsx EDITING is deliberately deferred (canvas engines break the theme-token system). CSV/TSV render via `CsvView` (text path, `csv-parse.ts`). `xls`/`ods` fall back to "Open externally" (`shell:open-path`, desktop-only).

## Filepath pills & attachments

- **Clicking ANY filepath pill "artifactifies" it and ALWAYS opens the artifact viewer, NEVER Project View.** `useOpenFilepath.ts` order: session match → **`artifacts:resolve-path`** (the host answers ONE path: tracked record, else the discovered record for an on-disk file inside the folder, else a reason) → else `appendVersion` (`user`/`read`) + `listSession` + select. A bridge WITHOUT the channel (rejects, or Android's `not-implemented-on-mobile`, which the shim RESOLVES as data) keeps the older project match (`listProject` first, `listAllFiles` only as the fallback). So a file Claude made via Bash/python (untracked) or in a temp dir still opens. cwd comes from `sessionCwd` (`SET_SESSION_CWD` from ChatView). The old `PROJECT_VIEW_OPENED` fallback was the bug — don't reintroduce.
  - **Why resolve-path (2026-09-11):** one tap downloaded 3,090 records (~1 MB) to a phone, and a file inside a nested git repo (discovery skips those) fell through to `appendVersion`, a write not bridged over remote. Over remote, `outside-project` shows a note instead of artifactifying; a stale tap (a newer tap in the same session) dispatches and writes nothing; a click shows "Opening <name>…" (`PILL_RESOLVE_STARTED` → `pillPending`) in the pill-error slot. Guards: `open-filepath.test.ts`, `session-drawer-pill-pending.test.tsx`.
  - **Remote gate** (`remote-server.ts` `fileReads`): `refuseUnknownRoot(root, {records:true})` before any lookup; a folder known only as a live session's cwd runs the lookup `trackedOnly` — `not-allowed` for anything unrecorded, WITHOUT touching it on disk. Outside the folder is decided from the strings alone (no existence oracle). Guards: `resolve-artifact-path.test.ts`, `remote-files.test.ts`.
- **`findBestMatch` (`components/filepath-match.ts`) prefers EXACT path matches over suffix**, case-insensitively (exact+suffix OR'd let a same-named file shadow the target). **With the chat's folder passed in, an ABSOLUTE clicked path matches ONLY by full absolute form** (folder + internal path, or external `absolutePath`) — the suffix pass opened the workspace-root `CLAUDE.md` for `wecoded-themes/CLAUDE.md`. Relative clicks keep exact-then-suffix. `buildArtifactifyArgs` resolves `..` via `canonicalize()` before internal/external classification; returns `null` for `~/` paths.
- **Discovered records come from ONE builder, `discoveredFileRecord()`** (`project-file-discovery.ts`), used by the discovery walk, `projectAllFiles`' union and `resolveArtifactPath` — never re-type the literal.
- **`detectFilepaths` accepts sentence-final `./!/?`** (only before whitespace/end) and rejects protocol-less domains via a short TLD list (so dotted dir names keep working). `html`/`htm`/`svg` are in the detector whitelist.
- **User-message attachment pills ride `ChatMessage.attachments` (exact picker paths), NOT regex** — picker paths contain spaces the space-joined `content` can't split back out. `content` stays the space-joined string (transcript dedup matches on it). Live-bubble only.

## Rule-overflow additions (2026-08-12, migrated verbatim from the path-scoped rule)

- **`+ Add file` IMPORTS (Move/Copy into the browsed folder), it does not pin.** `artifacts:import-file` (`artifacts/import-file.ts`) reuses `authorizeArtifactWrite` **without** `confirmed` (`.claude/`/dotenv destinations REFUSED). Data-safety invariants, each pinned by `import-file.test.ts`: never silent-overwrite, self-import guard, copy→verify→unlink for move (a copy that succeeds but whose source unlink fails returns the coded `MOVE_SOURCE_NOT_REMOVED` error truthfully — the file IS in the project — never a silent fork), temp-then-rename for replace, `{ force: true }` on the collision `listAllFiles` scan (the 10s discovery cache would otherwise serve a stale collision verdict). `.youcoded-import-*.part` temps are filtered from discovery AND sync `DEFAULT_IGNORES`.
- **`artifacts:get`/`save` enforce the D5 write boundary in MAIN and Kotlin** (`shared/artifacts/editable-path-policy.ts` + `EditablePathPolicy.kt`, ONE shared fixture; enforcement in `write-authorization.ts` runs on the SYMLINK-RESOLVED path): `.git`/`.youcoded`/credential paths never writable, `.claude` + `.env*` need the `confirmed` flag, everything else free. The renderer only MIRRORS this to hide the Edit affordance — never treat a renderer check as the boundary. Save also carries an mtime token (`baseMtimeMs`) — reject-on-conflict, never silent last-write-wins. Guards: `editable-path-policy.test.ts`, `write-authorization.test.ts`.
- **Android `get`/`save`/`read-binary` are REAL implementations (SessionService.kt), NOT stubs — any new guard on the desktop handlers must be mirrored in Kotlin.** The 2026-07-22 lesson: Kotlin save wrote `absolutePath!!` unchecked while desktop grew a boundary. Parity pinned by `ipc-channels.test.ts`.
- **`EXCLUDE` (`manualExcludes` write) has NO renderer caller** — the button went with the 2026-07-23 External Artifacts section. The handler is kept for legacy round-trip + visibility rule 2. In-folder files can't be excluded at all — hiding a file the user sees in their file manager would be a lie.

## Recorded paths: relative → internal, and the one-time repair (2026-08-13)

**The bug.** `resolveTrackedPath` had no branch for a RELATIVE recorded path, so it fell through to "genuinely external" and stored the relative string in `absolutePath` — a field `types.ts` documents as canonical-absolute. Every consumer then handed that to `realpath`/`fs.access`/`File()`, which resolve a relative path against the **process** cwd (`/home/destin` for a GUI-launched Electron app, `/` on Android), never the project root. Files that exist rendered as "no longer on disk", and the save path — whose ENOENT fallback resolves the PARENT — could have created a stray file outside the project.

**Why relative paths reach the tracker at all.** The NATIVE harness `Write`/`Edit`/`Read` accept a relative `file_path` and resolve it themselves with `path.resolve(ctx.cwd, p)` (`harness/tools/guards.ts`), but the transcript event carries the **raw** arg. `App.tsx` passes `session.cwd` as `projectRoot` — the *same value* the harness resolved against — so a relative recorded path is in-project by identity, not by inference. Step 3 must run AFTER the cross-OS remap, because `C:/…` is not absolute by POSIX rules and would otherwise be joined onto the root. `..` escapes stay external (the harness really did write outside the root) and are consistently refused everywhere rather than repaired.

**Five guard sites, not four.** `isAbsoluteRecorded` (exported from `write-authorization.ts`) must gate every site that turns a record into a filesystem path: `artifacts:get`, `artifacts:save`, `artifacts:check-existence`, `countArtifacts`, and **`renameArtifact`** — the last was missed in the original plan and is an `fs.rename` reachable from the drawer's click-to-rename, so a corrupt record could have moved a real file outside the project. It uses bare `path.isAbsolute`, which is already platform-correct (accepts `C:\…` on Windows, rejects it on POSIX where such a record is unaddressable anyway).

**The repair is gated on `reclassified === 0`, deliberately NOT on `$schema`.** `appendVersion` round-trips `$schema` from disk (it only writes it when CREATING a sidecar), so a version marker would read "repaired" while a pre-fix build running against the same folder kept producing new damage that would never be re-examined. The pure `migrateRelativeExternals` already reports whether anything changed, which costs one pass over an array `readSidecar` just parsed. It re-runs each stored external path through the FIXED classifier — so the repair cannot drift from the classifier — and MERGES a reclassified record that collides with an existing internal twin (versions deduped and ts-sorted, tags unioned, comments concatenated, older ULID survives) rather than leaving two internal records at one path. A `artifacts.json.pre-migration.bak` is written with `COPYFILE_EXCL` before the first rewrite; the OLDEST copy always wins, because a retry must never overwrite it with half-migrated state.
<!-- verify: {"test": "youcoded/desktop/tests/migrate-relative-externals.test.ts"} -->

**It runs inside read-only IPC handlers, so it must never throw.** `LIST_SESSION`, `LIST_PROJECT` and `LIST_ALL_FILES` were read-only before this; `atomicWrite` rethrows `ENOSPC`/`EROFS`/`EACCES`/`EPERM`, and `FilesTab` has no rejection handler, so an escaping error leaves the Files tab spinning forever. The catch logs and returns "nothing happened". Memo asymmetry is deliberate: CAS exhaustion does NOT memo (retries next call), an unexpected error DOES (no retry storm), and the memo is process-lifetime so a relaunch retries.

**The drawer labelling bug this exposed.** The Session Drawer picks rows by session but labelled every row from RECORD-GLOBAL data — `statusInfo` counted non-read versions across all sessions, and the timestamp was `artifact.lastModified`. A file merely *viewed* in this session therefore read `edited · <another session's date>`. It was invisible before because each mis-filed path had its own throwaway single-session record; merging them into the real record made it visible. Labels now come from `versionsInSession`/`lastModifiedInSession`, and the "recent first" sort uses the same value so order and dates agree.

**Known gaps (workspace `docs/roadmap/android-only.md`).** The sidecar is per-device and NEVER synced (`.youcoded/` is in `sync-spaces/guards.ts` `DEFAULT_IGNORES`), so Android keeps its own damaged copy — and because Android's `check-existence` is a stub, a damaged record there looks normal and opens blank. The `offset: 0` re-recording growth mechanism named here earlier was confirmed and closed 2026-08-15 — see "Replays are idempotent by `toolUseId`" under Tracking pipeline.
